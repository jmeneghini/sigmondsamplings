# Operators and correlators API review

Reviewed the current working tree on September 30, 2026, including the uncommitted effective-energy, coverage, plotting, and CLI additions. The original review below records that baseline; implementation follow-up is recorded here.

The label → metadata-only index → ordinary `SigmondData` → matrix wrapper architecture is a sound foundation. Joint resampling before nonlinear VEV subtraction, explicit handling of ambiguous stored forms, sample-by-sample complex transforms, and reuse of the existing analyzer are particularly good decisions. The main weaknesses are inconsistent entry points, identity and provenance becoming stale, and unnecessary metadata construction around otherwise efficient numerical operations.

Priorities below distinguish confirmed defects from proposed design improvements. P1 means an ordinary supported workflow can corrupt identity/provenance or give a misleading scientific result; P2 means a broken contract, unsupported common workflow, or incorrect display.

## Implementation follow-up

Implemented the twelve confirmed defects and the associated API simplifications:

- Operator strings/coordinates and XML preserve tetraquark displacement; pickle reconstructs fields and hashes. `to_sigmond()` and stored-key exports retain the exact compatibility spelling. Explicit parser kinds are validated, head-token dispatch replaces trial parsing, and GI labels can be built from a channel or generated by `transform`.
- Selection composes transformation columns correctly. Public matrix attachments validate coordinates, ensemble, sampling plan and sample length. Projections share one data-layer implementation and update both array and cell infos. Invalid significance/Hermiticity diagnostics stay NaN and cannot pass the check.
- Effective energies gather exact neighbours from sparse coordinates. Existing non-finite inputs follow drop/nan/raise; empty/neighbourless inputs raise domain errors. Shared integer validation rejects fractional values and bools. Forward kinds no longer require a lattice extent; symmetric constraints remain.
- Indices snapshot observable metadata and share eager buffers/deferred records. `loader.refresh_correlators()` rebuilds after collection edits. Coverage rejects unusable Im-only correlator/VEV records and separates incompatible directions; physical channel grouping remains. `matrix(channel)` and diagonal `correlator(op)` requests work. Single-correlator form inference lives in the library and preserves ambiguity errors.
- CLI requests accept `--key-form` for listing and plots, and default matrix time comes from the selected basis's complete coverage. Missing-cell hints use a structured exception. Public annotations and lazy type-checking exports describe the entry points.
- Transforms contract raw buffers and construct only final infos. Requests cache their series lookups. Hermitian assembly computes/resamples triangular traces once before expansion, preserving complex diagonals and joint VEV resampling. One-time heatmaps normalize and diagnose only their displayed slice. Lazy sample-length access uses the data-layer property. The unused style alpha and obsolete shift helpers were removed; plotting tails share a small helper with explicit public signatures.
- Tests use small interaction examples, including independent complex leave-one-out VEV subtraction and known jackknife significance. Optional binding checks probe the required symbols; optional fitting skips are confined to fit tests. RNG state resets per test. The README links an executable matrix example that runs without fitting dependencies.

Validation: full suite **1,088 passed, 32 skipped** in 21.58 s; the final metadata annotation/one-time diagnostic changes also passed **149 tests, 18 skipped**. Ruff and `git diff --check` passed. The unavailable compiled Sigmond oracle tests now skip correctly; `sigmond_query` compatibility checks run and pass. Compiled numerical comparisons still need an environment with working bindings. This repository has no existing CI configuration, so no speculative compiled-binding CI installation job was added.

Re-measured 12 operators × 48 times × 201 samples with the extended benchmark: lazy load 0.358 s; load without ObsMeta 0.986 s; index 0.123 s; one-time matrix 0.079 s; full lazy matrix 0.714 s; full eager matrix 0.088 s; square complex transform 0.115 s; sparse forward energy spanning 10⁹ time units below 0.001 s; one-time normalized heatmap 0.003 s. ## Confirmed defects

### 1. P1: Some tetraquark labels lose identity on pickle and parse/print round trips

Sources: [operator pickle reconstruction](/home/jmeneghini/code/lqcd/sigmondsamplings/sigmondsamplings/correlators/operators.py:176), [constructor displacement default](/home/jmeneghini/code/lqcd/sigmondsamplings/sigmondsamplings/correlators/operators.py:285), [Sigmond output omission rule](/home/jmeneghini/code/lqcd/sigmondsamplings/sigmondsamplings/correlators/operators.py:332).

For `tquuuu1m P=(0,0,0) A1um_1 QDX_1 D3`, the parsed displacement is 3. Its printed coordinate omits `D3`, following the reproduced Sigmond tetraquark quirk. Parsing that coordinate uses the constructor's default of 2. Consequently:

```python
op = BasicLapHOperator.from_sigmond("tquuuu1m P=(0,0,0) A1um_1 QDX_1 D3")
BasicLapHOperator.from_sigmond(str(op)) != op
pickle.loads(pickle.dumps(op)) != op
```

Explicit D2 and D3 operators that are distinct before pickling become equal afterward. The same issue reproduced for `tquudu3m`, `tquuss1p`, `tqsuss2p`, and `tqssss1p`. This affects multiprocessing, persisted metadata, and coordinate-based identity. The comment claiming that parsed displacement is the same either way is incorrect.

**Change:** preserve the actual fields when pickling, rebuilding the cached hash on reconstruction. More broadly, separate a lossless Python identity/coordinate from compatibility output that reproduces Sigmond's lossy omission. Do not simply change Sigmond output without accounting for exact stored-key compatibility. The local C++ source confirms that its constructor default and short-writer omission rule differ; copying both behaviors into Python does not make the round trip lossless.

### 2. P1: Selecting/reordering a transformed matrix leaves its transformation wrong

Sources: [select](/home/jmeneghini/code/lqcd/sigmondsamplings/sigmondsamplings/correlators/matrix.py:791), [composed transformation](/home/jmeneghini/code/lqcd/sigmondsamplings/sigmondsamplings/correlators/matrix.py:856).

`select()` slices values, VEVs, and stored masks, but `_replace()` retains the previous `Transformation` unchanged. A 2×2 identity transform followed by selecting only the second operator leaves a 2×2 coefficient matrix attached to a one-operator matrix. A subsequent 1×1 transform fails in `prev.coefficients @ T`. Selecting both operators in reverse order retains identity coefficients instead of swapping their columns; another transform can succeed while recording the wrong relationship to the original basis.

**Change:** select/reorder `transformation.coefficients[:, pos]` along with the current operators. Keep `source_operators` unchanged. Test a chain of transform → reorder/subset → transform against a direct contraction from the original matrix.

### 3. P1: Hermiticity diagnostics can report success on NaN data

Sources: [significance](/home/jmeneghini/code/lqcd/sigmondsamplings/sigmondsamplings/correlators/matrix.py:925), [Hermiticity sigma calculation](/home/jmeneghini/code/lqcd/sigmondsamplings/sigmondsamplings/correlators/matrix.py:940).

Both use `where(error > 0, value/error, where(value > 0, inf, 0))`. NaN comparisons are false. When the full-sample residual is NaN and its error is zero or NaN, the result is **0**, which reads as perfect agreement. Setting one full-sample off-diagonal value to NaN reproduced `check_hermitian().ok == True` and an off-diagonal residual of 0.

**Change:** distinguish an exactly zero uncertainty from a non-finite value or uncertainty. Preserve invalid diagnostics as NaN, and make `ok` require finite diagnostic values as well as values below the tolerance. Share the small ratio helper between significance and Hermiticity. This validation prevents a demonstrated misleading result.

### 4. P1: Non-finite input bypasses effective-energy failure policies

Source: [candidate construction](/home/jmeneghini/code/lqcd/sigmondsamplings/sigmondsamplings/correlators/effective.py:210).

Input presence is inferred using `np.isfinite(dense).all(axis=-1)` and then intersected across every correlator. A time coordinate that exists but contains a NaN resample is treated as absent before `on_fail` runs. With times `[1, 2, 3, 4]` and a NaN in one resample at time 2, both `on_fail="raise"` and `on_fail="nan"` silently return only time 3. The former never raises; the latter does not retain the affected times. In a multi-operator array, one operator can remove otherwise usable points from every other operator, including plotting's purported per-series failure behavior.

**Change:** derive neighbor availability solely from coordinates. Feed non-finite values at existing coordinates through the failure mask, then implement drop/nan/raise. Missing coordinates and failed numerical inputs are different conditions and need separate masks.

### 5. P2: Effective energy with no usable neighbors raises an internal reshape error

Source: [failure reduction](/home/jmeneghini/code/lqcd/sigmondsamplings/sigmondsamplings/correlators/effective.py:217).

Times `[1, 3, 5]` with `step=1` produce zero candidates. `reshape(-1, candidates.size)` becomes `reshape(-1, 0)`, which cannot infer the other dimension. The intended later error, explaining that no time has an effective energy, is never reached. A single-time input has the same problem. Empty time selections also reach `times.min()` before a domain-level error.

**Change:** handle the empty candidate/time cases before reductions, or use a reduction whose axes do not require inferring a dimension from zero elements. Test no-neighbor and one-time input explicitly.

### 6. P2: Cached indices become stale after supported metadata edits

Sources: [loader cache](/home/jmeneghini/code/lqcd/sigmondsamplings/sigmondsamplings/io/loader.py:177), [in-place metadata updates](/home/jmeneghini/code/lqcd/sigmondsamplings/sigmondsamplings/observable_collection.py:240), [index key storage](/home/jmeneghini/code/lqcd/sigmondsamplings/sigmondsamplings/correlators/index.py:57).

After accessing `loader.correlators`, `loader.observables.obs.update(name=...)` reparses each info but never invalidates the loader's cache or existing index keys. Renaming times 1 and 2 to 11 and 12 reproduced `loader.correlators.times == (1, 2)` while the indexed objects reported times 11 and 12. Matrix assembly can now regenerate old keys around renamed observations.

**Change:** choose and document one mutation contract. A simple explicit `refresh_correlators()` plus snapshot semantics is more understandable than an elaborate observer system. If transparent invalidation is required, it must cover filtered scopes and direct info mutation as well as updates on the parent collection; a collection-only version counter is insufficient for shared mutable objects.

### 7. P2: Discovery claims data are available when assembly rejects them

Sources: [coverage](/home/jmeneghini/code/lqcd/sigmondsamplings/sigmondsamplings/correlators/matrix.py:270), [lone imaginary check](/home/jmeneghini/code/lqcd/sigmondsamplings/sigmondsamplings/correlators/matrix.py:400), [channel grouping](/home/jmeneghini/code/lqcd/sigmondsamplings/sigmondsamplings/correlators/index.py:167), [coverage basis validation](/home/jmeneghini/code/lqcd/sigmondsamplings/sigmondsamplings/correlators/index.py:287).

Two reproduced inconsistencies:

- A lone Im-only diagonal has coverage `True`, and can be recommended by `available_bases()`, although `matrix()` rejects it. An Im-only VEV similarly passes the existence check for a connected request. These are metadata properties, so correcting coverage need not read samples.
- Forward and backward operators are grouped into one physical channel. Passing that channel to `coverage()` or `available_bases()` immediately fails the full-basis direction check. The discovery API cannot discover the usable forward-only or backward-only sub-bases.

**Change:** share a metadata-only usable-record predicate with assembly. Distinguish physical channel grouping from assembly-compatible candidate groups, or make sub-basis discovery treat incompatible directions as disconnected candidates. Keep the prohibition on mixing directions in an assembled matrix.

The claim that `available_bases()` implies assembly succeeds should also explicitly exclude the need for a bins resampling plan and runtime read failures; its purpose is metadata availability, not proof that every request parameter has been supplied.

### 8. P2: The public matrix constructor incompletely checks alignment

Source: [constructor](/home/jmeneghini/code/lqcd/sigmondsamplings/sigmondsamplings/correlators/matrix.py:659).

`stored` is checked only for dimension names and shape. Replacing its times with `[10, 20]` on values at `[1, 2]` is accepted. Grid plots then use the mask positionally, while selections use its coordinate labels, so provenance can be wrong or selection can fail. Attached VEVs are checked for operator coordinates and SamplingInfo but not ensemble or sample length. A VEV array with three samples is accepted alongside values with 41 samples under the same plan metadata.

**Change:** validate coordinates for the public constructor's aligned attachments, and reuse the ordinary ensemble/sample compatibility logic for VEVs. Keep validated internal construction lightweight. Add these specific checks at the public boundary instead of repeatedly revalidating the same invariant throughout operations.

### 9. P2: Absolute-value log plots draw asymmetric errors in the wrong direction

Source: [error-bar construction](/home/jmeneghini/code/lqcd/sigmondsamplings/sigmondsamplings/plotting/series.py:379).

Negative central values are displayed as `abs(y)`, but the lower and upper error offsets are not swapped. A bootstrap interval with central −10 and offsets `(3.2, 0.2)` is drawn at +10 with `(3.2, 0.2)`; reflecting the interval requires `(0.2, 3.2)`. Autoscaling also uses the unswapped offsets. Existing tests cover negative hollow markers and asymmetric array shapes independently, so this interaction goes undetected.

**Change:** swap plotted lower/upper errors where `points.absolute` is true, keeping hover values in the original signed convention. Use the reflected offsets for both drawing and limits. Marker hollowness alone is not the condition: provenance can make positive points hollow too.

### 10. P2: Explicit projected components do not consistently update observable metadata

Sources: [plot component helper](/home/jmeneghini/code/lqcd/sigmondsamplings/sigmondsamplings/plotting/correlators.py:52), [real diagonal metadata repair](/home/jmeneghini/code/lqcd/sigmondsamplings/sigmondsamplings/correlators/matrix.py:775), [generic real projection](/home/jmeneghini/code/lqcd/sigmondsamplings/sigmondsamplings/data.py:373).

The imaginary projection helper wraps `corr.data.imag` with the original infos. A projected imaginary series therefore has `is_complex=False` but `observable_info.re_im == "re"`, and its cell infos still say Re. The real diagonal method implements its own metadata-copying loop to correct a subset of the same concern.

**Change:** implement component projection once at the data layer, updating array and element infos consistently. Have the matrix and plotting layers call it. The plotter's public `corr` data should accurately describe its component, especially if subsequently inspected or written.

### 11. P2: The default CLI matrix time can come from another channel

Source: [matrix_records default time](/home/jmeneghini/code/lqcd/sigmondsamplings/sigmondsamplings/cli/corr.py:179).

The default is `index.times[0]` across the entire file. A first channel measured at time 1 and a second channel measured at time 4 cause a default query for the second channel to fail at time 1, even though its matrix is complete at time 4.

**Change:** choose the first complete time of the selected basis/form, preferably with shared metadata selection logic. Avoid materializing every time merely to show the first one.

### 12. P2: Fractional effective-energy arguments are silently truncated

Source: [integer conversion](/home/jmeneghini/code/lqcd/sigmondsamplings/sigmondsamplings/correlators/effective.py:188).

`step=1.9` is accepted and recorded as step 1; `time_extent` is converted the same way, and bools pass conversion. Other time and operator entry points reject non-integral values. This can calculate a different observable from the one requested.

**Change:** use the existing integer validation rule, accepting integral NumPy/Python values without silently rounding fractional values. A single shared integer helper can replace the divergent versions in labels, keys, matrix requests, and effective energies.

## Python usability and API design

1. **Make the common one-correlator request follow the same policy everywhere.** [Python](/home/jmeneghini/code/lqcd/sigmondsamplings/sigmondsamplings/correlators/index.py:326) defaults to `hermitian=False`; matrix assembly defaults to True; [CLI](/home/jmeneghini/code/lqcd/sigmondsamplings/sigmondsamplings/cli/corr.py:268) infers the stored form. Thus a HermMat-only file works through a matrix or CLI request but fails through `index.correlator(a, b)` unless the user knows to supply the flag. Move any inference into a shared library policy, preserving ambiguity errors when several meaningful forms exist. Distinguish following a stored HermMat convention from explicitly symmetrizing independent plain records. Do not silently prioritize conflicting forms.

2. **Accept a Channel consistently.** `coverage(channel)` and `available_bases(channel)` work for a valid single-direction candidate set, but `matrix(channel)` raises `TypeError: 'Channel' object is not iterable`. Matrix can use the same `_basis()` resolution already present. This is a small change with a large discovery-to-analysis usability benefit.

3. **Make diagonal requests and generated GI labels less verbose.** Consider `index.correlator(op)` meaning its diagonal, with `source=op` by default. Add a channel-based GI factory or let `transform(T, name="ROT")` generate its labels, keeping explicit labels supported when the caller needs them. Users currently restate isospin, strangeness, momentum, irrep, row, name, and each index even though the source matrix already determines the channel. An example factory `GenIrrepOperator.from_channel(channel, name="ROT", index=k)` would centralize that construction without adding another label abstraction.

4. **Remove unnecessary lattice-extent requirements from forward calculations.** Both forward kernels use ratios/differences and do not use T. The unconditional `T >= 8` and `step <= T//4` restrictions come from Sigmond's shared C++ calculator constructor; they do not protect the forward calculation itself. Require T for symmetric kinds, and validate positive integer step plus actual neighbor availability for forward kinds. Preserve the four numerical conventions without forcing users to invent an unrelated extent for a forward ratio. This is a proposed API change, not a numerical disagreement with Sigmond.

5. **Expose actual Python signatures to editors.** Many user-facing results and delegated properties are untyped, several APIs accept strings without declaring them, and the subpackage's dynamically loaded names lack a matching stub/type-checking declaration. `transform` annotates only GI objects while its docstring accepts strings; `CorrelatorMatrixInfo.operators` accepts strings at construction despite its annotation; `position()` accepts only objects unlike adjacent methods. Add concrete input/output types and Literal choices, and mirror lazy exports under TYPE_CHECKING or in a small stub. Good notebook completion and actionable errors matter more here than additional convenience aliases.

6. **Separate immutable basis identity from assembly options conceptually.** `CorrelatorMatrixInfo` currently combines basis, requested symmetrization, and connectedness; those flags then participate in cell metadata and output. `key_form`, `info.hermitian`, and actual numeric Hermiticity answer different questions. Document those distinctions clearly; especially explain that an assembled Hermitian request already enforces off-diagonal agreement, so its later check is mainly an imaginary-diagonal check. It cannot diagnose discrepancies that averaging erased. Keep a simple non-Hermitian request for inspecting stored directional disagreement. Avoid turning these distinctions into another hierarchy of request/result classes.

7. **Provide the CLI escape hatch the library error recommends.** Ambiguous forms tell users to pass `key_form=`, but `ss query corr` has no `--key-form`. Thread a single explicit option through listing/plot assembly rather than maintaining a CLI-only form-selection workaround. Replace the CLI's string matching and substitution of library exceptions with a small structured exception only where coverage context is actually needed.

8. **Keep metadata identity unambiguous.** `CorrelatorObsInfo(name=key1.to_sigmond(), key=key2)` is accepted with conflicting identities: `.name` says time 1 while `.time` says time 10 in a reproduced example. Prefer construction from one input; if both inputs must remain supported, establish consistency once at that boundary. Also make `parse_operator(kind=...)` explicit about how it treats existing objects and tagged strings: currently `parse_operator(bl, "general")` returns the BL object and even ignores an invalid kind for an existing object.

9. **Keep wrapper-preserving selection easy to recognize.** `sel()`/`at()`/`correlator()` return SigmondData, while `select()`/`sel_times()` retain the matrix wrapper. These are useful distinctions, but the README should state them directly. If simplifying the API, one `select(operators=..., times=...)` method can replace two wrapper-preserving paths and make provenance updates happen in one place. Do not remove domain-specific accessors solely because each delegates to selection.

## DRY, KISS, and unnecessary code

- **Remove temporary metadata from transforms.** Each `apply_matrix()` builds placeholder cell infos, twice, before `transform()` replaces them with correlator infos. Use a shared raw-buffer contraction helper for both the generic map and the matrix transform, then wrap final metadata once. Keep validation in the public operations. This reduces real work and construction complexity; avoid adding a public `unchecked` mode.
- **Reuse sample-length access.** There are private `_sample_length` implementations in [index](/home/jmeneghini/code/lqcd/sigmondsamplings/sigmondsamplings/correlators/index.py:30) and [lazy](/home/jmeneghini/code/lqcd/sigmondsamplings/sigmondsamplings/lazy.py:104), plus the data-layer property. Give lazy data a metadata-only override of the existing property and use that consistently. This avoids reaching into `_record` from the correlator layer.
- **Resolve a request's stored series once.** `_Request.cell_times()` repeatedly calls `_lookup()`, which constructs and validates a fresh CorrelatorInfo. Form counts, complete times, coverage, and error reporting recreate those lookups and sets. Store the direct/flipped dictionaries for a request once and reuse them. Cache within the request, not in a new global invalidation system.
- **Unify component handling and statistical ratios.** Findings 3 and 10 are cases where duplication has already produced incorrect behavior. Fixing them with small shared helpers improves correctness and reduces code.
- **Use `dataclasses.replace` where appropriate.** `with_backwards()` and `with_index()` repeat positional constructor fields. `replace(self, backwards=...)` / `replace(self, index=...)` express the change directly and still run dataclass validation and rebuild caches. Preserve semantic methods when they are useful to users.
- **Simplify automatic grammar dispatch.** BL and GI head tokens are distinguishable under the supported grammar. `parse_operator("auto")` currently tries both parsers, collects successes/errors, and handles ambiguity. Choose from the head token/tag; preserve detailed failure messages. The `flavor in TETRAQUARK_SHORT` branch in `_parse_single_hadron()` is unreachable from `_parse_basic()`: all those long names contain underscores and are routed to `_parse_multi_hadron()` first.
- **Stop checking already-established restrictions within one operation.** A transform's finite coefficient check is repeated by both `apply_matrix` calls. Its per-label channel check is followed by `CorrelatorMatrixInfo` checking the new basis's channel agreement again. Consolidate at an internal boundary while retaining public entry-point validation. Requiring definite momentum may be a domain policy worth keeping; checking momentum and channels is not generally dead code.
- **Remove the unused `SeriesStyle.band_alpha` field.** It is documented but the renderer always takes fit alpha from `FitOverlay.band_alpha` and marker alpha from `HMarker.band_alpha`. Changing the style field has no effect. Choose one owner instead of retaining a configuration knob that does nothing.
- **Reduce forwarding boilerplate cautiously.** Correlator plotters repeat many identical plotting-tail parameters and dictionary forwarding. A small shared internal tail helper can reduce repetition, but retain explicit typed public signatures; replacing everything with arbitrary `**kwargs` would hurt the stated usability goal.
- **Do not generalize solely to satisfy DRY.** Separate label/key/observable identity types represent distinct concepts. The exact/greedy basis search has a real bounded-use tradeoff. The batched lazy I/O path, per-sample VEV subtraction, duplicate-basis rejection, ensemble/sample compatibility checks, and ambiguity errors prevent real errors. They should remain.

## Performance opportunities, in priority order

1. **Eliminate discarded transform infos**, as measured above. The implementation already uses numerical contractions; optimizing those before removing metadata work targets the smaller portion of the profiled cost.
2. **Avoid materializing a dense time span for sparse effective-energy inputs.** The current allocation scales with `max(times)-min(times)+1`, not the number of supplied rows. Resolve t±step with sorted-coordinate searches or a time→position mapping and gather neighboring rows. This also removes duplicated positional shift/missing-grid machinery and naturally fixes coordinate presence versus numerical validity. Do not silently use the next stored time as t+step.
3. **Assemble each Hermitian pair once.** When both directions exist, both output directions gather and average the same pair. Filling one triangle and its conjugate reduces averaging work and the `other` buffer; retain recorded complex diagonals. Chunking this stage can also reduce peak memory. Measure before adding intricate indexing machinery.
4. **Resample only unique independent traces.** The current full square is built before bins resampling, including completed symmetric counterparts. Resampling stored/averaged triangular traces jointly with VEVs and expanding afterward can reduce bins workload. Conjugation and averaging are linear and commute with the shared resampling operation; nonlinear VEV subtraction must still happen afterward. Compare against independent bin statistics and shared draw plans.
5. **Build a one-time heatmap from one time.** `plot_heatmap(value="normalized")` normalizes all times, creates all placeholder metadata, then selects the displayed time. Extract normalization factors once and scale only the displayed slice for the heatmap. Keep `matrix.normalized()` for callers needing the entire array. Similarly, compute one-time Hermiticity diagnostics directly for one-time views when worthwhile.
6. **Cache immutable derived label metadata only if profiling justifies it.** BL channel access repeatedly computes momentum/strangeness and constructs Channel; index `channels`, `times`, and series listings also rebuild results. Construction-time derived channel values can help large metadata queries. Return cheap immutable results or fresh mappings so caller mutation cannot poison caches.

The measured lazy assembly remains dominated by reading many small HDF5 datasets. Metadata-request simplifications are useful, but unlikely to transform end-to-end read time on their own. A future consolidated numeric storage layout would be a separate, optional format decision; exact compatibility with existing Sigmond files must remain intact.

## Test quality and simplification

The numerical tests are substantially better than a superficial suite: hand-computed complex Hermitian assembly, nonlinear full-estimate VEV subtraction, rectangular complex transforms, closed-form effective energies, lazy/eager comparisons, and I/O round trips test meaningful behavior. Preserve these.

The weaknesses are interaction coverage, optional-dependency gating, and some tests that assert implementation structure without testing the advertised value semantics:

- **Scope optional imports to tests that need them.** [test_plotting_correlators.py](/home/jmeneghini/code/lqcd/sigmondsamplings/tests/test_plotting_correlators.py:216) uses module-level `pytest.importorskip("optimagic")` midway through the file. Collection skips the entire module when optimagic is unavailable, including previously defined SeriesPlotter and marker tests unrelated to fitting. Move it into the fit fixture/tests or split fitting tests into a separate file.
- **Probe the required Sigmond capabilities, not only its root import.** [label tests](/home/jmeneghini/code/lqcd/sigmondsamplings/tests/test_correlator_labels.py:35) and [effective-energy tests](/home/jmeneghini/code/lqcd/sigmondsamplings/tests/test_correlator_effective.py:281) assume importing `sigmond` establishes binding availability. Lazy imports break that assumption in this environment. Have the optional oracle fixture import/access the exact required compiled symbols and clearly skip on unavailable dependencies. Maintain a separate CI job with working compiled bindings so oracle tests really run.
- **Test transformation chains.** The current rectangular transform test checks repeated transforms but never selection between them. One three-step behavior test detects both failure and silent lineage corruption without a large fixture.
- **Extend tetraquark testing to round trips across color and displacement.** The C++ comparison checks emitted strings; the ordinary pickle test exercises only a few forms. Independently assert field/identity preservation under parse/print, XML, and pickle for the omission cases. External parity and internal invariants are different requirements.
- **Cross relevant plotting conditions.** The asymmetric error test checks only yerr shape and hover text. Assert actual reflected interval endpoints for a negative value on a log plot; retain a separate positive hollow point to avoid conflating sign and provenance.
- **Add invalid-value and sparse-neighbor cases.** Small arrays are enough to test NaN full values, NaN errors, non-finite resamples, one time, no adjacent time, and fractional arguments. Test policies and diagnostic truth values, not exact internal error text.
- **Make expected scientific results independent.** The joint bins test computes its expected samples through the same private `_block_resample` used by production. It does also check the full estimator, which is valuable. Strengthen it with manually calculated leave-one-out means for a tiny jackknife example, or controlled bootstrap draws, including correlated complex VEVs. The effective-energy drop-rule test derives its expected mask from the production kernel; closed forms and binding comparisons should remain the independent checks.
- **Use known-value fixtures for significance tests.** The current significance expected result delegates to the same analyzer properties used by implementation. A small hand-calculated mean/variance test exposes whether invalid data and error scaling are handled correctly; no complex fixture is needed.
